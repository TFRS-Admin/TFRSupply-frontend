# Architecture Decision Records

ADRs document decisions that affect architecture, data ownership, integrations, deployment, security, or operating rules.

## When an ADR is required

Create an ADR when a decision:

- Changes or constrains architecture.
- Affects protected files.
- Changes data ownership or source of truth.
- Changes external integrations.
- Affects deployment, CI, security, or release processes.
- Will guide multiple future PRs.

## Status lifecycle

- Proposed
- Accepted
- Rejected
- Deprecated
- Superseded

## Naming convention

Use zero-padded numbers and kebab-case:

```text
docs/adr/001-short-title.md
```
