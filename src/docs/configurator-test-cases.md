# Configurator Test Cases

_Last updated: Sprint 15 — SKU Selector QA_

---

## How to Run Tests

In the browser console while on any page:

```js
import { runEngineTests } from '/src/domain/configuration/engineTests.js';
runEngineTests();
```

Or in the Admin Debug page (future integration point).

---

## Test Fixture

All engine tests use a self-contained fixture JSON (defined inside `engineTests.js`) with:
- 4 steps: `size` (required), `color` (required), `mounting` (optional), `accessories` (optional, multi-select)
- 1 dependency rule: `size=large` requires `mounting`
- 2 compatibility rules: `size=large + mounting=magnetic` = hard exclude; `color=amber + size=small` = soft warn
- `skuOptions[]` — 5 existing catalog SKUs (source of truth, no template)

> **Sprint 15 change:** `skuTemplate` removed from fixture and engine. SKUs are now resolved by filtering `skuOptions[]` against selections, never generated by string interpolation.

## SKU Selector Test Cases

### SKU-1: No Selections → All SKUs Are Candidates

**Goal:** With no filters active, every catalog SKU is a candidate.

**Input:**
```js
selections = {}
```

**Expected from `resolveSkuMatch`:**
- `skuStatus` → `'multiple'`
- `matchingSkus.length` → 5 (all fixture SKUs)
- `selectedSku` → `null`

**UI:** No SKU match box shown (no selections yet).

---

### SKU-2: Partial Selection → Narrowed Candidates

**Goal:** One selection filters the list but multiple SKUs still match.

**Input:**
```js
selections = { size: 'small' }
```

**Expected:**
- `skuStatus` → `'multiple'`
- `matchingSkus.length` → 3 (TST-SM-R, TST-SM-B, TST-SM-A)
- `selectedSku` → `null`

**UI:** "N SKUs match current selections — complete remaining steps to resolve" (amber).

---

### SKU-3: Exact Selection → Single SKU Resolved

**Goal:** All attribute-bearing steps filled, exactly one SKU matches.

**Input:**
```js
selections = { size: 'small', color: 'red' }
```

**Expected:**
- `skuStatus` → `'matched'`
- `selectedSku` → `'TST-SM-R'`
- `matchingSkus.length` → 1

**UI:** "Matching SKU: TST-SM-R" (green).

---

### SKU-4: No Matching SKU (Invalid Combination)

**Goal:** User selections don't correspond to any existing catalog SKU.

**Input:**
```js
selections = { size: 'large', color: 'amber' }  // TST-LG-A not in fixture
```

**Expected:**
- `skuStatus` → `'none'`
- `matchingSkus.length` → 0
- `selectedSku` → `null`

**UI:** "No matching SKU found for this combination." (red).

---

### SKU-5: Accessories Do Not Affect SKU Resolution

**Goal:** Multi-select steps are excluded from the attribute filter.

**Input:**
```js
selections = { size: 'large', color: 'blue', accessories: ['cable-10', 'alley'] }
```

**Expected:**
- `skuStatus` → `'matched'`
- `selectedSku` → `'TST-LG-B'`
- `matchingSkus.length` → 1

**UI:** Accessories appear in summary below the matched SKU, not in the SKU itself.

---

### SKU-6: SKU Resolution is Attribute-Exact (Not Substring)

**Goal:** Filters use exact `skuSegment` value match, not substring/contains.

**Fixture SKUs:** `TST-SM-R`, `TST-LG-R` (both have color=R)
**Input:** `{ color: 'red' }` only

**Expected:**
- `matchingSkus` → [ TST-SM-R, TST-LG-R ] (color matches both)
- `skuStatus` → `'multiple'`

---

### SKU-7: SKU Attribute Not Present → Pass-Through (SKU Is Unconstrained)

**Goal:** If a SKU doesn't declare an attribute, it is not excluded by that filter.

**Scenario:** A future SKU with no `color` attribute would match any color selection.
**Current fixture:** All SKUs have both `size` and `color` — no pass-through needed. Documented for future use.

## Existing Test Cases (Rules Engine)

### TC-1: Happy Path

**Input:** `selections = { size: 'small', color: 'red' }`

**Expected:**
- `isComplete` → `true`
- `completion` → `100`
- `violations` → `[]`
- `pendingSteps` → `[]`
- `selectedSku` → `"TST-SM-R"` (resolved from `skuOptions[]`)
- `skuStatus` → `'matched'`

---

### TC-2: Incomplete Path

**Input:** `selections = { size: 'small' }` — color missing

**Expected:**
- `isComplete` → `false`
- `completion` → `50`
- `pendingSteps` → `[{ id: 'color', label: 'Color' }]`
- `selectedSku` → `null` (multiple matches, not yet resolved)
- `skuStatus` → `'multiple'`
- UI: "Required steps remaining: Color"

---

### TC-3: Dependency Path

**Input:** `selections = { size: 'large' }`

**Expected:**
- `depRequirements.length` → `1`
- `depRequirements[0].triggerLabel` → `"Large"`
- `depRequirements[0].targetStepLabel` → `"Mounting"`
- `completion` → `33` (1 of 3 required: size✓, color✗, mounting✗)
- After filling `color` + `mounting`: `completion` → `100`, `isComplete` → `true`

---

### TC-4: Exclusion Path

**Input:** `selections = { size: 'large', color: 'red', mounting: 'magnetic' }`

**Expected:**
- `violations.filter(v => v.type === 'excludes').length` → `1`
- `isComplete` → `false` (conflict blocks ready state)
- UI: `Incompatible: "Large" + "Magnetic"`

---

### TC-5: Warning Path

**Input:** `selections = { size: 'small', color: 'amber' }`

**Expected:**
- `violations.filter(v => v.type === 'warns').length` → `1`
- `isComplete` → `true` (required steps filled, no hard exclusions)
- `selectedSku` → `"TST-SM-A"` (warns-only does not block resolution)

---

### TC-6: Accessory Path

**Input sequence:**
```js
sel = applySelection(session, {}, 'accessories', 'cable-10')
sel = applySelection(session, sel, 'accessories', 'alley')
sel = applySelection(session, sel, 'accessories', 'cable-10')  // toggle off
```

**Expected after sequence:**
- `sel.accessories` → `['alley']`
- `getSelectedAccessories` → `[{ optionLabel: 'Alley Light Kit', priceModifier: 95 }]`

**Full accessory + SKU:**
```js
selections = { size: 'small', color: 'red', accessories: ['cable-10', 'alley'] }
```
- `selectedSku` → `"TST-SM-R"` (accessories never affect SKU resolution)
- `accessories.length` → `2`
- `isComplete` → `true`

## Edge Cases

### EC-1: Unknown stepId in applySelection
```js
applySelection(session, {}, 'nonexistent-step', 'foo')
// Expected: returns original selections unchanged
```

### EC-2: resolveSkuMatch with empty skuOptions
```js
// session with no skuOptions → { matchingSkus: [], selectedSku: null, skuStatus: 'none' }
```

### EC-3: Dependency rule with no active trigger
```js
getActiveDependencies(session, { size: 'small' })
// Expected: [] — dep only fires on size=large
```

### EC-4: Compatibility violation — only one side selected
```js
getCompatibilityViolations(session, { size: 'large' })
// Expected: [] — mounting not yet selected, no violation
```

### EC-5: isStepComplete on multi-select with empty array
```js
isStepComplete({ accessories: [] }, { id: 'accessories', multiple: true })
// Expected: false
```

## Navigator-Specific Scenarios (navigator-configurator.json)

These use real Navigator product data. SKU resolution uses `skuOptions[]` from `navigator-configurator.json`.

| Scenario | Selections | Expected |
|---|---|---|
| Full police build — Blue/Blue 53" | length=53in, color=blue-blue | `selectedSku="NAV-SLB-53-BB"`, `skuStatus='matched'` |
| Full police build — Red/Blue 53" | length=53in, color=red-blue | `selectedSku="NAV-SLB-53-RB"`, `skuStatus='matched'` |
| Partial — length only | length=45in | `skuStatus='multiple'`, 2 candidates (45-BB, 45-RB) |
| No match — Red/White combo | color=red-white | `skuStatus='none'` (RW not in skuOptions) |
| Fire apparatus + magnetic | vehicle=fire-apparatus, mounting=magnetic | Hard exclusion fires, `isComplete=false` |
| Fire apparatus + 60in | vehicle=fire-apparatus, length=60in | Dependency notice shown |
| Amber on patrol sedan | color=amber, vehicle=patrol-sedan | Soft warning fires, does NOT block `isComplete` |
| Accessories selected | accessories=[cable-10, alley-kit] | Both in summary, `selectedSku` unchanged |
| Incomplete (no color) | length=45in, mounting=perm | `isComplete=false`, `pendingSteps=[color]`, `skuStatus='multiple'` |
